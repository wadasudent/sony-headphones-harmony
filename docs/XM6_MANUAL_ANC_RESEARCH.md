# XM6 手动降噪档位调查

调查日期：2026-11-11。结论：尚未发现可验证的 XM6 手动 ANC 强度接口，未实现档位控制，也未向耳机发送未知参数。

## 已核对的证据

参考 [SonyHeadphonesClient 固定提交](https://github.com/mos9527/SonyHeadphonesClient/tree/68dfced0403b38114b77f2b374e606ce12a206a8)。

- [NcValue 枚举](https://github.com/mos9527/SonyHeadphonesClient/blob/68dfced0403b38114b77f2b374e606ce12a206a8/libmdr/include/mdr/ProtocolV2T1.hpp#L1185) 定义单路、双路和自动等取值；这些是模式枚举，不能视为强度刻度或 XM6 支持证据。
- 同一文件的 `NcAsmRetParamModeNcDualModeSwitchAsmSeamlessNa`（5703 行）与 `NcAsmSetParamModeNcDualModeSwitchAsmSeamlessNa`（6044 行）描述 `0x19` 读写格式，其中没有 `NcValue` 成员。其他报文类型中才出现该成员，不能跨类型套用偏移。
- [上游处理实现](https://github.com/mos9527/SonyHeadphonesClient/blob/68dfced0403b38114b77f2b374e606ce12a206a8/libmdr/src/HeadphonesV2T1.cpp#L88) 将 `0x19` 的附加字段解释为自动环境声开关和噪声适应灵敏度。
- 本项目在设备公布功能 `0x6D` 时选择 `0x19`，已有检查覆盖其 9 字节状态。此处沿用社区协议解释，不宣称完成芯片或固件逆向。

## 当前报文的字段

以下偏移从 MDR payload 首字节计数，不包含传输层帧头。

| 偏移 | 含义 |
| --- | --- |
| 0 | 参数回复 `0x67`、通知 `0x69`，或设置 `0x68` |
| 1 | 查询类型 `0x19` |
| 2 | 状态变化标记 |
| 3 | 降噪/环境声总开关 |
| 4 | 降噪或环境声模式 |
| 5 | 环境声普通/人声模式 |
| 6 | 环境声等级 |
| 7 | 自动环境声开关 |
| 8 | 自动环境声检测灵敏度 |

不能把偏移 6 当作 ANC 强度，也不能把偏移 8 的高/标准/低当作降噪档位。协议名称包含“DUAL”也不代表存在单/双路切换接口。`NC_TEST_MODE` 的存在同样不能证明可以调整强度。

## 后续实机调查

1. 连接手机和 XM6，记录耳机型号、固件、已公布功能以及当前合法状态；不记录设备地址等无关信息。
2. 仅对耳机明确公布的查询类型，核对能力回复与状态回复；例如 `0x60,0x19` 为能力查询，`0x66,0x19` 为参数查询。能力回复中的环境声等级列表不作为 ANC 档位证据。
3. 如具备运行 Sony 官方 App 的设备与蓝牙抓包条件，对照合法操作前后的报文。官方 App 没有相关操作时，普通使用抓包也未必能暴露隐藏接口；HDC 连接本身不代表已具备蓝牙抓包能力。
4. 只有找到独立候选字段、设备支持证据和可恢复的有效范围，才评估写入实验；随后需验证回读及受控条件下的实际降噪变化。ACK 或主观瞬时变化不足以证明强度控制成功。

本轮 HDC 未发现手机或平板，因此以上实机步骤尚未执行。若不存在对外控制接口，继续研究可能涉及固件分析，不能保证普通应用能够实现。
